# P2.10 Python-only core equivalents

Issue: GitHub [#129](https://github.com/michelreifenrath/pyqtgraph_to_cpp/issues/129)

This decision applies the full-port parity policy to three Python-only core helpers. It is a decision/equivalence artifact only; it does not add C++ headers, C++ sources, CMake wiring, tests, manifest status changes, or generated dashboard updates.

## Source-of-truth policy

- `docs/parity-contract.md` is the governing parity contract from GitHub [#95](https://github.com/michelreifenrath/pyqtgraph_to_cpp/issues/95) / P0.01. It defines the native C++ port scope and already records Numba helpers, Python reload helpers, and frozen-application packaging helpers as non-port by default.
- `docs/proposed-issues/VALIDATION-GUIDE.md#decision-doc` defines the proof for this issue type: record the conservative default, rationale, affected manifest entries, accepted C++ equivalence or explicit non-port decision, and follow-up policy; add C++ tests only if executable behavior changes.
- `docs/local-validation.md` defines local-only completion evidence for docs-only decision issues.
- `port_manifest.yaml` pins the upstream reference to PyQtGraph `pyqtgraph-0.14.0`, commit `a20028b98294b9cc8770f2015a92eb342224b788`.

## Conservative default

Python interpreter lifecycle helpers, Python frozen-application or zip packaging helpers, and Python/Numba acceleration wrappers are non-port for the native C++ library unless a future concrete native C++ runtime, packaging, or benchmark-backed performance issue owns equivalent behavior.

The accepted C++ equivalence is native C++/Qt/OpenCV behavior implemented under future scoped issues only when needed. P2.10 does not create compatibility shims for Python packaging, Python module reloading, or Numba.

## Rationale and equivalence decisions

### `pyqtgraph/frozenSupport.py`

This helper adapts Python file and directory lookups for frozen applications and zip-packaged Python runtime layouts. That behavior is Python packaging support, not native Qt/C++ plotting behavior.

Decision: do not create `include/pyqtgraph/frozenSupport.hpp` or `src/pyqtgraph/frozenSupport.cpp` for P2.10. Equivalent C++ deployment behavior may be owned only by a future concrete C++ packaging/deployment issue.

### `pyqtgraph/reload.py`

This helper scans Python modules, reloads Python code, and mutates Python functions/classes/instances through interpreter and object-model machinery. Native C++ does not expose an equivalent Python module reload surface.

Decision: do not create `include/pyqtgraph/reload.hpp` or `src/pyqtgraph/reload.cpp` for P2.10. Equivalent native runtime behavior would require a future scoped C++ runtime issue; no such behavior is required by this issue.

### `pyqtgraph/functions_numba.py`

This helper wraps NumPy-like array operations with Python/Numba JIT acceleration. The native C++ port should satisfy performance needs through C++/OpenCV implementations and targeted benchmarks, not a Numba compatibility layer.

Decision: do not create `include/pyqtgraph/functions_numba.hpp` or `src/pyqtgraph/functions_numba.cpp` for P2.10. Equivalent performance work belongs in future benchmark-backed C++ implementation issues only when a concrete workload requires it.

Future native C++ packaging, runtime, or performance work must be opened as a concrete scoped issue before any equivalent behavior is implemented.
