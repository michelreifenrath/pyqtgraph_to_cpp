# Implementation Plan

## Goal
Establish a focused P0.06 upstream-oracle probe contract, fixture artifacts, and labeled validation entry point without touching production source outside owned oracle/test/docs files and narrow CTest wiring.

## Tasks
1. **Add the failing P0.06 pytest contract first**: Create focused tests that describe the oracle artifact and mismatch behavior before implementation.
   - File: `tests/oracle/test_P0_06_oracle_probe.py`
   - Changes: Add tests named with `P0_06`, using the existing `tests/oracle/test_numeric_oracles.py` fake-checkout/subprocess style. Tests should initially call a missing script such as `oracle/scripts/generate_P0_06_oracle_probe.py` and assert:
     - `--help` exposes `--root`, `--check`, `--format`, and `--emit-mismatch-example`.
     - Normal mode writes `oracle/fixtures/P0_06/probe_contract.json` and `oracle/fixtures/P0_06/mismatch_failure_example.txt` deterministically.
     - JSON fixture contains `schema_version`, `issue: P0.06`, `reference` with `repo`, `ref`, `pinned_commit`, `checkout_path`, `pyqtgraph_version`, and `pyqtgraph_commit`, `inputs`, `expected`, and `tolerance`.
     - `--check` fails on a deliberately stale fixture with a mismatch message that includes fixture path, JSON pointer/key, expected value, actual value, and tolerance.
   - Acceptance: Running `python3 -m pytest -q tests -k P0_06` immediately after this task must fail red because `oracle/scripts/generate_P0_06_oracle_probe.py` does not exist or the expected artifacts are absent. Save the red command/output in an owned artifact, for example `oracle/fixtures/P0_06/red_failure.txt`, or document the exact output in the implementation notes if the team prefers not to keep red logs.

2. **Implement the minimal P0.06 oracle generator**: Add the script only after the red pytest is captured.
   - File: `oracle/scripts/generate_P0_06_oracle_probe.py`
   - Changes: Implement a small CLI following `oracle/scripts/generate_numeric_oracles.py` conventions: read `reference/source.lock`, validate required keys, verify checkout commit matches `pinned_commit`, run an isolated reference probe with `QT_QPA_PLATFORM=offscreen` and `PYTHONDONTWRITEBYTECODE=1`, then write/check deterministic artifacts under `oracle/fixtures/P0_06/`.
   - Acceptance: `python3 -m pytest -q tests -k P0_06` progresses past missing-script failures and validates deterministic fixture generation/check mode.

3. **Define the P0.06 fixture contract**: Add the expected fixture generated by the script.
   - File: `oracle/fixtures/P0_06/probe_contract.json`
   - Changes: Store deterministic JSON with sorted/stable key order. Required content:
     - `schema_version`: `1`
     - `issue`: `P0.06`
     - `reference`: include upstream lock values plus `pyqtgraph_version` and `pyqtgraph_commit`; expected pinned ref is from `reference/source.lock` (`pyqtgraph-0.14.0`, commit `a20028b98294b9cc8770f2015a92eb342224b788`) unless the lock changes before implementation.
     - `inputs`: small deterministic probe inputs, e.g. scalar/vector values used by the reference probe.
     - `expected`: exact reference probe outputs for those inputs.
     - `tolerance`: explicit numeric policy; use exact comparison (`absolute: 0.0`, `relative: 0.0`) unless a selected probe involves floating-point roundoff, in which case document a small absolute/relative tolerance in both fixture and docs.
   - Acceptance: `--check` succeeds when the committed fixture matches freshly generated output.

4. **Add the required mismatch example artifact**: Capture a stable example of the failure text produced when a fixture value is changed.
   - File: `oracle/fixtures/P0_06/mismatch_failure_example.txt`
   - Changes: Store one representative mismatch failure, e.g. a stale `expected` value showing path, expected, actual, tolerance, and instruction to regenerate/check the fixture.
   - Acceptance: Pytest asserts the file exists and contains the same diagnostic shape emitted by `--check` on a stale temp fixture.

5. **Document how to add and validate P0.06-style oracle probes**: Keep documentation under the issue-owned oracle docs glob.
   - File: `docs/upstream-oracle-probes.md`
   - Changes: Document the artifact schema, pinned upstream source requirement, how `reference/source.lock` is used, fixture input/output expectations, tolerance policy, mismatch example purpose, and the focused validation commands.

## Risks
- `ctest --preset dev -L P0.06` is not meaningful unless a labeled test is added; keep the shared change limited to one new CTest entry and label.
- Adding Python discovery to CMake may affect configuration; prefer the smallest `find_package(Python3 REQUIRED COMPONENTS Interpreter)` placement inside `if(BUILD_TESTING)` and stop if project policy rejects a required Python test dependency.
- `reference/source.lock` is read-only for this issue; stop if the pinned upstream checkout is missing, dirty, or does not match `pinned_commit` rather than changing the lock.
- Production C++/Qt source is out of scope. Stop and escalate if satisfying P0.06 appears to require changes under `include/`, `src/`, `examples/`, or non-oracle tests beyond the focused CTest wiring.
- If the chosen probe needs nonzero floating tolerance, document the reason and exact policy in both fixture and docs; do not silently use approximate comparisons.
- If artifact expectations conflict with owned-file globs, stop and ask for scope approval before writing outside `oracle/**`, `tests/oracle/test_*oracle*`, `docs/**oracle*`, or narrow shared wiring.
